# Dogfood UX fixtures (tracked, synthetic-only)

This directory is tracked in git. Everything under it must be **100%
synthetic** — machine-generated placeholder text only, never a copy (even
partial, even briefly) of a real vault or real personal notes. See
`docs/dogfood/README.md`'s "This rule is about real vault content, not
synthetic content" note for why that distinction is safe to make.

## What's here

- `vault-1/` — a small synthetic Obsidian vault (originally generated by
  `scripts/dogfood/init.sh`'s heredoc) used to give anyone checking out
  this repo a zero-setup vault for UI/UX dogfooding: point a local daemon
  instance at it as a sync root, then exercise the web viewer
  (`/node`, `/review`, `/search`, `/sync`, `/dashboard`) and/or the
  Obsidian plugin (`plugin-obsidian/`) against real reconciled data
  instead of an empty vault.

## Rules

1. **Never add real content here.** If you want to dogfood against your
   own real notes, use the external scratch flow in
   `docs/dogfood/README.md` instead (`scripts/dogfood/init.sh <name>`),
   which never touches this directory.
2. This directory holds vault *content* only (`.md` files). It never holds
   a daemon's `config.toml`, `store.db`, tokens, or logs — those stay in a
   scratch dir outside the repo (e.g.
   `$HOME/.local/share/akasha-dogfood/<name>/`), pointed at this
   directory's path as their sync root, exactly as `scripts/dogfood/init.sh`
   points at an external `vault-1/` today. `vault-1/.obsidian/` is
   `.gitignore`d (repo root `.gitignore`) — whatever Obsidian writes there
   when you open this vault (workspace layout, plugin bookkeeping, and
   especially a `plugins/tm-hub` link to a locally built plugin) is
   machine-local and must never be committed. If `git status` ever shows
   anything under `vault-1/.obsidian/` as untracked-but-not-ignored, that's
   a bug in the `.gitignore` pattern, not something to `git add`.
3. If you hand-edit notes here while dogfooding, keep them synthetic
   (nonsense/placeholder prose is fine and preferred — the point is
   exercising sync/reconciliation mechanics, not content). Anchors
   (`^tm-...`) are expected to change as the daemon reconciles edits;
   that's normal and fine to commit.
4. Never store a bearer token, `.bootstrap_token`, or any other daemon
   secret under this directory.
5. `vault-1/note1.md` ships with `^tm-new` placeholders (not minted
   `^tm-<id8>` anchors) deliberately — mirroring `scripts/dogfood/init.sh`'s
   own template. This means a fresh daemon/DB mints them cleanly on first
   reconcile with **zero** violations. If you dogfood against this fixture
   and let the daemon mint real ids, **don't commit that back** — `git
   checkout` the file afterward (or otherwise restore the `^tm-new` form)
   so the next person also gets a clean first run. A fresh DB has no memory
   of ids minted by someone else's earlier session, so committing minted
   ids here would make every subsequent fresh run show spurious
   `E_UNKNOWN_ANCHOR` violations for content it never minted itself
   (empirically hit this exact issue standing this fixture up).
6. **Never point a plugin's `.obsidian/plugins/tm-hub` junction/symlink at
   `plugin-obsidian/` (the source directory) from inside this vault.** Its
   `node_modules/` and `TESTPLAN.md` sit inside that tree; since sync-root
   file discovery walks every `*.md` under the registered root, doing so
   pulls in dozens of unrelated `README.md`/`CHANGELOG.md` files from
   plugin dependencies (and `TESTPLAN.md`'s own literal example anchor) as
   noise violations. Build the plugin (`npm run build` in
   `plugin-obsidian/`) and link/copy only the install artifacts
   (`manifest.json`, `main.js`, `styles.css` if present) into
   `vault-1/.obsidian/plugins/tm-hub` — never the whole source tree.
